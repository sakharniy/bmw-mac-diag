# bmw-mac-diag

**Диагностика BMW на маке через дешёвый кабель K+DCAN — без Windows и без виртуальной машины.**

Двойной щелчок, выбор цифры в меню: прочитать и стереть ошибки всех блоков, смотреть живые показания двигателя
с графиками, получить отчёт о поездке в браузере. Работает на [EdiabasLib](https://github.com/uholeschak/ediabaslib)
(открытая реализация EDIABAS, автор Ulrich Holeschak).

[English version](README.md)

> **Статус: ранняя версия.** Проверено на одной машине — BMW E93 320d 2010 (дизель N47), мак на Apple Silicon,
> клон кабеля FT232RL K+DCAN. Для других BMW E-серии (E90–E93 и т.п.) с D-CAN или K-line должно работать, но это не проверено.
> **F-серия и новее — пока нет**: там нужен ENET-кабель, его поддержку можно добавить, если найдётся кто-то с F-кой потестить.
> Отчёты и профили для других машин приветствуются.

## Что умеет

- **Ошибки всех блоков**: один опрос показывает все блоки с количеством ошибок; номер блока — и видны его ошибки.
- **Стирание ошибок** выбранного блока — сначала программа читает ошибки и сохраняет их в файл, потом спрашивает подтверждение.
- **Живые показания двигателя** ~8 раз в секунду, у каждого — мини-график за 30 секунд, всё пишется в CSV.
- **Графики в реальном времени** (клавиша G): задание и факт наддува и воздуха, температура перед сажевым фильтром —
  сразу видно, успевают ли турбина и EGR за тем, что требует блок двигателя.
- **Отчёт о поездке** в браузере по записи: синхронные графики, значения при наведении, увеличение, сводка, таблица.
  Работает без интернета — удобно переслать сервису.
- **Сам узнаёт машину**: спрашивает блок двигателя, какой он вариант, и выбирает или создаёт профиль показаний.
- **Работает и без файлов BMW** (базовый режим): стандартные показания двигателя OBD, коды ошибок всех блоков
  (без расшифровки), номера деталей — см. [Без файлов SGBD](#без-файлов-sgbd-базовый-режим).
- Интерфейс на русском и английском (как в системе).

## Что нужно

- Мак (проверено на Apple Silicon; Intel должен работать, не проверено).
- **Кабель K+DCAN** на чипе FTDI FT232R (обычный дешёвый, с переключателем; клоны работают).
  Драйвер в macOS встроенный, ставить ничего не нужно. Кабель появляется как `/dev/cu.usbserial-XXXXXXXX`.
- **.NET 10 SDK**.
- **Файлы SGBD** (`*.PRG`, `*.GRP`) — описания блоков управления. Это собственность BMW, в проект они **не входят**,
  их нужно найти самостоятельно (они идут в составе пакетов диагностического ПО BMW). См. [Файлы SGBD](#файлы-sgbd).
  Без них программа работает в [базовом режиме](#без-файлов-sgbd-базовый-режим).

## Установка

```sh
# 1. .NET 10 SDK — либо (спросит пароль администратора):
brew install --cask dotnet-sdk
#    либо только для своего пользователя, без прав администратора:
curl -sSL https://dot.net/v1/dotnet-install.sh | bash -s -- --channel 10.0

# 2. скачать программу
git clone https://github.com/sakharniy/bmw-mac-diag.git
```

Всё — при первом запуске программа сама соберётся (один раз скачает официальный релиз EdiabasLib, ~90 МБ,
и проверит его контрольную сумму). Собрать вручную: `./build.sh`.

## Быстрый старт

1. Вставьте кабель в мак и в машину, **включите зажигание**.
2. Дважды щёлкните **`BMW Diag.command`** в папке `bmw-mac-diag`. Откроется Терминал.
   (Совет: перетащите этот файл в Dock — будет запускаться одним щелчком.)
3. **Первый запуск** всё проверяет сам:
   - **файлы SGBD** — если их нет, так и скажет и подскажет, куда их положить; можно перетащить свою папку в окно;
   - **ключевые файлы** — `T_GRTB.PRG` (нужен, чтобы узнавать блоки), `D_MOTOR.GRP`, файлы блоков из списка опроса;
   - **машину** — спросит блок двигателя, какой он вариант (например, `D72N47B0`), и выберет подходящий профиль
     из `profiles/` или **создаст его** по таблице показаний самого блока (обороты, температуры, наддув, воздух, EGR,
     сажевый фильтр, напряжение… плюс уровень топлива из приборки, если она отвечает).
     Автоматические профили хранятся в `~/.config/bmw-mac-diag/profiles/`. Машины рядом нет — определить можно позже в настройках.
4. Дальше — меню:

```
  1  Живые показания двигателя (экран + запись CSV)
  2  Ошибки двигателя
  3  Ошибки всех блоков
  4  Определить блок двигателя
  5  Стереть ошибки блока (выбор из списка)
  6  Настройки (папка SGBD, профиль машины, язык)
  7  Отчёт по записи (откроется в браузере)
  0  Выход
```

- **1 — живые показания.** Клавиши: **G** цифры ⇄ графики, **Q** или Ctrl+C — назад в меню. Всё пишется в `logs/live-*.csv`.
- **3 — опрос.** Блоки пронумерованы, рядом количество ошибок; введите номер — увидите ошибки блока, `с` — стереть их.
- **5 — стирание.** Выберите блок (в списке количество ошибок по последнему опросу). Перед стиранием ошибки с подробностями
  сохраняются в `logs/faults-before-clear-*.txt`; стирание — только после ввода `да` (или `yes`). После стирания блок
  читается заново: ошибки, активные прямо сейчас, сразу вернутся.
- **6 — настройки.** Четыре шага; у каждого видно текущее значение, **Enter — оставить как есть**.
- **7 — отчёт.** Выберите запись (Enter — последняя), отчёт откроется в браузере.

**Язык:** как в системе macOS; поменять — в настройках, ключом `--lang ru|en` или переменной `BMWDIAG_LANG`.
Тексты ошибок берутся из самих файлов SGBD (немецкий/английский) и не переводятся.

## Кабель

1. `./bmwdiag ports` (или шапка меню) должен показать `/dev/cu.usbserial-…`.
2. Переключатель на кабеле выбирает протокол: **D-CAN для машин примерно после 03/2008**, K-line (пины 7+8) — для старых.
   При ошибке `IFH-0003` первым делом щёлкните переключатель — это самая частая причина, и это не поломка.
3. Кабелем одновременно может пользоваться только одна программа: закройте живые показания, прежде чем запускать другое.
4. После работы вынимайте кабель: он питается от машины.

В инструкциях под Windows просят выставить у кабеля FTDI latency timer = 1 мс — на маке это не нужно.

## Файлы SGBD

Каждому блоку нужен свой файл SGBD. Скопируйте их в `ecu/` без подпапок или укажите свою папку в настройках.

Групповые файлы (`D_MOTOR.GRP`, `D_EGS.GRP`, …) спрашивают блок, кто он, и сами выбирают вариант — для этого нужен
**свежий `T_GRTB.PRG`** (таблица соответствий). Если групповой файл пишет *No variant found* — `T_GRTB.PRG` старый;
тогда можно вызывать нужный `.PRG` напрямую.

**Нужен правильный вариант.** Старый или чужой вариант часто нормально читает ошибки (это стандартная часть), но живые
показания выдаёт мусором или пустыми. Пример с тестовой машины: через `D71N47A0.PRG` ошибки читались, а все живые
показания были пустыми («Too less data») — на самом деле блок `D72N47B0`; `T_GRTB.PRG` определяет это по
`ID_VAR_INDEX` / `ID_DIAG_INDEX` блока.

## Без файлов SGBD (базовый режим)

Если папка SGBD пуста (или с ключом `--basic`), программа говорит с машиной напрямую, только стандартными запросами
на чтение. Меню пишет об этом в шапке и предлагает то, что так работает:

| | базовый режим | с файлами SGBD |
|---|---|---|
| Живые показания | стандартные показания OBD, которые отдаёт двигатель (на тестовой машине 19: обороты, нагрузка, педаль, охлаждающая жидкость, давление во впуске, расход воздуха, EGR, давление в рампе, температура катализатора, скорость, напряжение…), ~5 раз в секунду; графики, CSV и отчёт как обычно | всё, что есть в блоке (у N47 больше 1600 показаний): задание и факт наддува и воздуха, сажа в фильтре… |
| Ошибки | код BMW (шестнадцатеричный) и состояние (активна сейчас / в памяти) у всех блоков, P-коды OBD двигателя — **без расшифровки** | коды с расшифровкой и подробностями |
| Определение блоков | номер детали BMW, дата, индекс диагностики / вариант у каждого блока | + вариант SGBD |
| Стирание ошибок | нет | да |

Адрес каждого блока на шине берётся из списка опроса (`"addr"` в `scan/e9x.json`). Проверено на E93 (D-CAN);
машины с K-line не проверялись.

```sh
./bmwdiag --basic                       # меню в базовом режиме
./bmwdiag live   --basic                # стандартные показания OBD
./bmwdiag scan   --basic                # коды ошибок всех блоков
./bmwdiag faults --basic [KOMB87.PRG]   # один блок (по умолчанию двигатель; или адрес, напр. 0x60) + P-коды OBD
./bmwdiag ident  --basic                # номера деталей всех блоков
```

## Команды

Всё, что есть в меню, доступно и командами (`./bmwdiag --help` — полный список):

```sh
./bmwdiag                             # меню
./bmwdiag setup                       # настройки
./bmwdiag detect                      # узнать двигатель, выбрать или создать профиль
./bmwdiag ident  D_MOTOR.GRP          # что за блок и какой вариант
./bmwdiag faults D_MOTOR.GRP          # прочитать ошибки
./bmwdiag clear  D_MOTOR.GRP          # стереть ошибки (сначала сохранит их, спросит подтверждение)
./bmwdiag scan                        # ошибки всех блоков из scan/e9x.json
./bmwdiag live   [--graphs]           # живые показания с профилем из настроек
./bmwdiag report [файл.csv]           # отчёт в браузере (по умолчанию — последняя запись)
./bmwdiag jobs   KOMB87.PRG           # что умеет блок
./bmwdiag job    KOMB87.PRG STATUS_TANKINHALT              # любой job, все результаты
./bmwdiag job    D72N47B0.PRG _ARGUMENTS FS_LESEN_DETAIL   # какие аргументы у job'а
./bmwdiag job    D72N47B0.PRG FS_LESEN_DETAIL 0x4B81       # job с аргументами ("a;b;c" или "hex:01 02")
./bmwdiag watch  D72N47B0.PRG STATUS_UBATT --seconds 30    # повторять job, CSV всех числовых результатов
./bmwdiag raw    D72N47B0.PRG "22 40 22"                   # сырой запрос KWP2000 (только чтение)
```

Опции: `--port <dev>`, `--ecu <папка>`, `--log <файл>` / `--no-log`, `--graphs`, `--basic`, `--lang ru|en`,
`--trace` (трассировка обмена EDIABAS в `trace/`). Настройки хранятся в `~/.config/bmw-mac-diag/config.json`:

```json
{ "ecuPath": "~/bmw/ecu", "port": "auto", "profile": "~/bmw-mac-diag/profiles/n47-dde721.json", "language": "auto" }
```

## Профили

Профиль (JSON) говорит, какой SGBD использовать и какие показания выводить: подписи (с необязательными русскими `*_ru`),
единицы, масштаб, разделы, графики. [`profiles/n47-dde721.json`](profiles/n47-dde721.json) — готовый пример для
дизеля N47D20C. Обычно писать его не нужно — `detect` создаст сам. Если хотите сделать или подправить вручную:

1. `./bmwdiag jobs <SGBD>` — ищите `STATUS_MESSWERTBLOCK_LESEN` (блоки двигателя DME/DDE BMW) или отдельные `STATUS_…`.
2. `./bmwdiag job <SGBD> _TABLE MesswerteTab` — таблица показаний: колонка `ARG` идёт в `"arg"`, `RESULTNAME` в `"result"`.
3. Проверка: `./bmwdiag job <SGBD> STATUS_MESSWERTBLOCK_LESEN "JA;INMOT;IUBAT"`.
4. Показатели со своим job'ом — через `"job"` вместо `"arg"`; показатели из других блоков — в `"extras"`.
5. Графики: `"charts": [{ "title": "Boost", "title_ru": "Наддув", "series": ["SPLAD", "IPLAD"], "minSpan": 0.3 }]` —
   до двух показателей в одних единицах на график; без `"charts"` берутся обычные пары «задание / факт».

Список опроса [`scan/e9x.json`](scan/e9x.json) (E90–E93) — простой список `name` / `sgbd`; для других моделей сделайте свой.

## Если не работает

| Сообщение | Что значит |
|---|---|
| `IFH-0018` | не открывается порт — кабель не вставлен в мак или его занимает другая программа (например, открытые живые показания) |
| `IFH-0003` | кабель не отвечает — выключено зажигание или **щёлкните переключатель D-CAN/K-line** |
| `SYS-0010` | машина не отвечает — зажигание включено? кабель вставлен? повторите (первая попытка иногда не проходит) |
| `IFH-0009` | блок не отвечает — не тот SGBD, блока нет в машине, или он отвечает только на заведённом двигателе |
| `No variant found` | групповой файл не знает блок — нужен свежий `T_GRTB.PRG` или вызывайте `.PRG` напрямую |
| живые показания пустые / мусор, `Too less data` | не тот вариант SGBD — см. [Файлы SGBD](#файлы-sgbd) |

## Ограничения и безопасность

- Проверено только на одной машине (E93, D-CAN). F-серия и новее пока не поддерживаются: их диагностика идёт через ENET
  (Ethernet через тот же OBD-разъём, кабель со штекером RJ45). EdiabasLib умеет ENET, так что поддержку можно добавить,
  если найдётся кто-то с F-кой и ENET-кабелем потестить.
- Всё только на чтение, кроме стирания ошибок. `raw` разрешает только сервисы чтения.
- Осторожнее с незнакомыми job'ами на блоках безопасности: при переборе SGBD и status-job'ов на блоке DSC (ABS)
  на тестовой машине на секунду загорелась лампа ABS (ошибка не записалась). Обычное чтение на ходу проблем не давало.
- Не смотрите в экран за рулём. Пусть смотрит пассажир — или просто пишите запись и смотрите отчёт потом.
